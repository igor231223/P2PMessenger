# P2P Messenger — Инструкция

Зашифрованный мессенджер без центрального сервера. Сообщения идут напрямую между устройствами (peer-to-peer) или через relay-сервер если прямое соединение невозможно. Сервер видит только зашифрованные байты — ключи шифрования никогда его не покидают.

---

## Быстрый старт

### 1. Скачай приложение

Готовый файл: **`P2PMessenger.exe`**  
Запускается без установки. Двойной клик — и всё.

### 2. Первый запуск — регистрация

При первом запуске появится окно входа.

**Если аккаунта нет** → нажми «Зарегистрироваться»:
- Придумай никнейм (минимум 3 символа)
- Придумай пароль (минимум 4 символа)
- Повтори пароль
- Пока вводишь никнейм — справа будет видно свободен он или занят
- Нажми «Зарегистрироваться»

**Если аккаунт уже есть** → вкладка «Войти»:
- Никнейм
- Пароль
- Нажми «Войти»

### 3. Последующие запуски

Приложение запомнит тебя автоматически. Окно входа больше не появится — сразу откроется мессенджер.

Чтобы выйти из аккаунта — удали файл `C:\Users\ТвоёИмя\.p2pmessenger\config.ini`

---

## Как начать переписку

### Написать новому человеку

1. Нажми кнопку **+** в верхнем правом углу боковой панели
2. Введи никнейм собеседника (он должен быть зарегистрирован и запущен)
3. Нажми «Подключиться»
4. Подожди — в шапке чата появится статус подключения

> Собеседник должен быть онлайн в этот момент. Если его нет — увидишь «не удалось подключиться» и кнопку «🔄 Повторить».

### Написать тому, с кем уже общались

Прошлые собеседники автоматически появляются в списке слева при каждом запуске. Просто кликни на нужный контакт — соединение установится само.

---

## Статусы соединения

| Статус в чате | Что значит |
|---|---|
| `● подключение…` | Идёт попытка прямого P2P соединения |
| `● в сети` + 🟢 `direct` | Прямое соединение, трафик не идёт через сервер |
| `● в сети` + 🟠 `relay` | Соединение через relay-сервер (шифрование такое же) |
| `● не в сети` | Соединение не установлено |

**Почему relay, а не direct?**  
Если один из вас использует VPN, корпоративную сеть или мобильный интернет — прямое соединение может быть невозможно физически. Relay — это автоматический fallback: трафик идёт через сервер, но остаётся зашифрованным E2E. Сервер не может прочитать сообщения.

---

## Шифрование

Каждый чат защищён:

- **X25519 ECDH** — обмен ключами при соединении. Сервер ключи не видит.
- **ChaCha20-Poly1305** — каждое сообщение шифруется отдельно с уникальным nonce.
- Значок 🔒 на каждом отправленном сообщении означает, что оно было зашифровано перед отправкой.

---

## История сообщений

История хранится локально на твоём компьютере:
```
C:\Users\ТвоёИмя\.p2pmessenger\messages.db
```

- Сохраняется между запусками
- В боковой панели показывается последнее сообщение и время
- Удалить историю — просто удали этот файл

---

## Настройки сервера

Нажми **⚙** в верхнем правом углу боковой панели.

| Поле | По умолчанию | Описание |
|---|---|---|
| Хост | `193.188.20.124` | IP или домен сервера |
| UDP порт | `5555` | Порт для P2P соединений |
| HTTP порт | `5556` | Порт для входа/регистрации |

> Настройки сохраняются. После смены сервера перезапусти приложение.

---

## Кнопка «Повторить подключение»

Появляется если соединение не удалось. Нажми чтобы попробовать снова. Полезно если:
- Собеседник только что запустил приложение
- Сеть переключилась (Wi-Fi → мобильный интернет)
- Сервер был недоступен

## Поднять свой сервер

Тебе нужен любой VPS с Ubuntu/Debian и открытыми портами **5555/UDP** и **5556/TCP**.

### Деплой одной командой

На своём компьютере (где лежит `deploy.sh`):

```bash
bash deploy.sh root@IP_СЕРВЕРА
```

Скрипт сам установит Docker, соберёт образ и запустит сервер. В конце выведет адрес и порты.

### Открыть порты (если закрыты)

```bash
# UFW (Ubuntu)
ufw allow 5555/udp
ufw allow 5556/tcp

# iptables
iptables -A INPUT -p udp --dport 5555 -j ACCEPT
iptables -A INPUT -p tcp --dport 5556 -j ACCEPT
```

### Проверить что сервер работает

```bash
curl http://IP_СЕРВЕРА:5556/check_nick?nick=test
# Должно вернуть: {"available": true}
```

### Посмотреть кто сейчас онлайн

```bash
curl http://IP_СЕРВЕРА:5556/debug
```

### Удалить сервер полностью

```bash
ssh root@IP_СЕРВЕРА "docker rm -f p2p-rendezvous && docker rmi p2p-rendezvous && rm -rf /data/p2p"
```

## Что делать если не работает

**Не могу зарегистрироваться / войти**
- Проверь что сервер доступен: `curl http://193.188.20.124:5556/check_nick?nick=test`
- Проверь настройки сервера (⚙)

**Соединение с собеседником не устанавливается**
- Убедись что собеседник запущен и онлайн
- Нажми «🔄 Повторить подключение»
- Если ты или собеседник используете VPN — relay подключится автоматически после 6 сек
- Если relay тоже не работает — проверь, не блокирует ли файрвол Windows исходящий UDP

**Windows Firewall блокирует приложение**
При первом запуске Windows может показать запрос файрвола. Нужно разрешить «частные сети» (Private networks). Если запрос не появился:
1. Панель управления → Брандмауэр Windows
2. Разрешить приложение → Добавить → указать `P2PMessenger.exe`
3. Разрешить для частных и публичных сетей

**Приложение запускается, но сразу закрывается**
- Убедись что Python не нужен — это автономный .exe
- Попробуй запустить от имени администратора

## Файлы приложения

```
P2PMessenger.exe              — само приложение

C:\Users\ТвоёИмя\.p2pmessenger\
├── config.ini                — настройки (сервер, токен сессии)
└── messages.db               — история переписок (SQLite)
```

Чтобы полностью удалить приложение — удали exe и папку `.p2pmessenger`.

## Технические детали

| Параметр | Значение |
|---|---|
| Протокол P2P | UDP + hole punching |
| Fallback | TURN relay через rendezvous-сервер |
| Шифрование | X25519 ECDH + ChaCha20-Poly1305 |
| Аутентификация | PBKDF2-HMAC-SHA256 (200 000 итераций) |
| Хранение паролей | Только хеш + соль, сервер plaintext не видит |
| История | SQLite локально, не синхронизируется |
